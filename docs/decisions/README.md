# Architecture Decision Records

Material decisions that affect future work live here as ADRs.

## Format

```text
ADR-NNN-short-title.md
```

Each ADR should include: **context**, **decision**, **consequences**, and **status** (proposed | accepted | superseded).

## When to write an ADR

- Booking source of truth
- Google Calendar integration approach
- CMS / content strategy
- Authentication or payments (if added later)
- Major third-party vendor choices

Do **not** create ADRs for trivial implementation choices (e.g. single utility function naming).
